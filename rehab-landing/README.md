# رحاب — اللاندينج بيج

صفحة تعريفية بمنصة رحاب للسكن النسائي، وفيها استمارة تستقبل نوعين من الطلبات
— **باحثة عن سكن** أو **مالك عقار** أو **مستثمر** — وتحفظها في Supabase.

المجلد **مستقل تمامًا** عن مشروع Flutter: لا يستورد منه شيئًا ولا يتأثر به.
المشترك الوحيد هو الهوية البصرية — الألوان منسوخة من
`Rehab_Project/rehab/lib/core/constants/app_colors.dart`، والشعار من
`assets/images/logo_removebg.png`.

## التشغيل في ثلاث خطوات

### ١) جهّزي الجدول في Supabase

**Supabase Dashboard → SQL Editor → New query**، والصقي محتوى
`supabase/partner_leads.sql` ثم شغّليه. آمن للتشغيل أكثر من مرة.

الملف ينشئ جدول `partner_leads`، وينسخ إليه بيانات `investor_leads` القديم
إن كان موجودًا. **لا يحذف الجدول القديم** — احذفيه بنفسك متى ما تأكدتِ من النقل.

### ٢) ضعي المفاتيح

انسخي `config.example.js` إلى `config.js` واملئي القيمتين من
**Project Settings → API**:

```js
window.REHAB_CONFIG = {
  supabaseUrl: "https://xxxxxxxx.supabase.co",
  supabaseAnonKey: "eyJhbGci...",
};
```

قبل ملء المفاتيح تعمل الصفحة في **وضع المعاينة**: النموذج يتحقق من المدخلات
ويعرض شاشة النجاح، لكنه يقول صراحةً إن البيانات لم تُحفظ — لا يدّعي نجاحًا وهميًا.

### ٣) شغّليها

ملف واحد بلا أي عملية بناء:

```bash
cd rehab-landing
python -m http.server 8000
# ثم افتحي http://localhost:8000
```

> افتحيها عبر خادم محلي لا بالنقر المزدوج. المتصفح يمنع طلبات `file://`
> من الوصول لـ Supabase.

للنشر: ارفعي المجلد كما هو على Netlify أو Vercel أو GitHub Pages.

## الاستمارة

الخطوة الأولى تحدّد **الصفة**، ويتغيّر بعدها كلٌّ من الأسئلة **وعدد الخطوات**:

| | باحثة عن سكن | مالك عقار | مستثمر |
|---|---|---|---|
| عدد الخطوات | **٢** | ٣ | ٣ |
| الخطوة ١ | الاسم، البريد، الجوال، المدينة | نفسها | نفسها |
| الخطوة ٢ | نوع السكن المطلوب، موعد الحاجة، الصفة، الميزانية، الحي المفضّل — **والملاحظات والموافقة** | عدد الوحدات، موعد الاستعداد للعرض، الحي، الغرف المتاحة، السعر الشهري، نوع الوحدة | صفة المستثمر، حجم الاستثمار، الأفق الزمني، مجالات الاهتمام، الجهة |
| الخطوة ٣ | — | وصف موجز للوحدة، موافقة | رابط لينكدإن أو الموقع، ملاحظات، موافقة |

مسار الباحثة خطوتان عن قصد: نيّتها أقل التزامًا من المستثمر، وإطالة المسار
عليها تعني انسحابها. فتُنقل الملاحظات والموافقة إلى خطوتها الثانية برمجيًا،
ويُبنى شريط التقدّم وعنوان «الخطوة ١ من ٢» بعدد خطوات الصفة المختارة.

الجدول فيه قيد `partner_leads_shape` يرفض أي خلط بين الصفات: طلب `investor`
بلا صفة مستثمر يُرفض، و`owner` بلا جاهزية للعرض يُرفض، و`seeker` بلا نوع سكن
مطلوب يُرفض — التحقق في قاعدة البيانات لا في المتصفح وحده.

خيارات نوع الوحدة (`شقة خاصة / شقة مشتركة / غرفة ضمن شقة مشتركة / وحدة أو دور كامل`)
مبنية على تصنيف التطبيق نفسه في شاشة إضافة إعلان.

## عن المفتاح العلني

المفتاح `anon` مصمَّم ليكون ظاهرًا في المتصفح، وهذا طبيعي. الحماية في RLS:

- **الإدخال فقط** مسموح للزائر — **ولا توجد سياسة `SELECT` إطلاقًا**. حتى لو
  أخذ أحدهم المفتاح من كود الصفحة، لا يمكنه قراءة سطر واحد. أنتِ تقرأينها
  من لوحة تحكم Supabase.
- **التحقق مكرَّر في قاعدة البيانات**: صيغة البريد، أطوال الحقول، حدود عدد
  الغرف والسعر، والموافقة الصريحة على التواصل.
- **بريد واحد لكل نوع** — فهرس فريد على `(lead_type, email)`. أي أن الشخص نفسه
  يستطيع التسجيل مرة كمستثمر ومرة كمالك عقار، دون تكرار النوع ذاته. وتعرض
  الصفحة رسالة مناسبة بدل خطأ تقني.

لا تضعي مفتاح `service_role` هنا أبدًا.

## قراءة الطلبات

واجهتان جاهزتان ترتّبان الأولوية:

```sql
select * from public.seeker_leads_triage;    -- قائمة الانتظار، الأقرب حاجةً أولًا
select * from public.owner_leads_triage;     -- الملّاك
select * from public.investor_leads_triage;  -- المستثمرون
select * from public.demand_summary;         -- ملخّص الطلب لكل مدينة
```

`demand_summary` هي الأهم عند التحدث إلى مستثمر: تعطيك لكل مدينة عدد
المسجّلات، وكم منهن يردن سكنًا مشتركًا، وكم منهن حاجتهن عاجلة، ومتوسط
الميزانية. وهذه أرقامٌ حقيقية من قائمة انتظاركم، لا تقديرات.

عمود `status` لمتابعتك: `new` → `contacted` → `qualified` أو `passed`.
الزائر لا يستطيع تغييره — يبدأ دائمًا `new`.

## مزايا التسجيل المبكر

قسم `#early` — لوحة برقوقية داكنة قبل الاستمارة مباشرة، تعرض ثلاث مزايا
للمسجَّلات مبكرًا. وهي القسم الوحيد الداكن في الصفحة عمدًا: يكسر إيقاع
الأقسام الفاتحة، ويصنع بؤرة بصرية تدفع القارئة إلى الاستمارة.

> ⚠️ **قرار تجاري يخصّك:** نسبة **١٥٪** ومدة الخصم مكتوبتان في الصفحة
> كقيمة مبدئية. راجعيهما قبل النشر — فما يُكتب هنا وعدٌ تلتزمين به أمام
> كل مَن يسجّل. ابحثي في `index.html` عن `خصم ١٥٪` (وفوقها تعليق تنبيه).

المزايا الثلاث المعروضة:

| الميزة | ما تعنيه عمليًا |
|---|---|
| خصم على أول عقد | يُطبَّق على أول إيجار يُتَمّ عبر رحاب بعد الإطلاق |
| دخول مبكر | فتح الحساب وتصفّح الوحدات قبل الفتح العام |
| أولوية في المطابقة | عرض الملف على شريكات السكن الأعلى توافقًا أولًا |

وأسفل القسم سطر تحفّظ مقصود: «التسجيل مجاني ولا يترتّب عليه أي التزام،
وتُطبَّق شروط المزايا المعلنة عند الإطلاق» — لا تحذفيه، فهو ما يحمي الوعد
من أن يُقرأ التزامًا مطلقًا.

## بريد التواصل

يُكتب في موضع واحد فقط، أعلى السكربت في `index.html`:

```js
var CONTACT_EMAIL = "rehab.team.sa@outlook.sa";
```

ما دام على قيمته الأولية تبقى كتلتا البريد مخفيّتين تمامًا — أسفل الاستمارة
وفي التذييل — فلا يُنشر رابط بريد معطوب. وبمجرد وضع عنوان صحيح يظهر
الموضعان معًا برابط `mailto:` جاهز.

## تعديل النصوص

كل نص مكتوب باللغتين داخل الوسم نفسه:

```html
<h3 data-ar="توثيق الهوية عبر نفاذ" data-en="Identity verification via Nafath">توثيق الهوية عبر نفاذ</h3>
```

عدّلي `data-ar` و`data-en`، واجعلي النص الظاهر بينهما مطابقًا للعربي.
زر `EN / AR` يبدّل اللغة واتجاه الصفحة معًا. النص الإرشادي للحقول في
`data-ph-ar` و`data-ph-en`.

الألوان متغيّرات CSS في أعلى `<style>`، والوضع الداكن يعيد تعريف المتغيّرات
نفسها — فتغيير لون في `:root` يسري على الصفحة كاملة.
